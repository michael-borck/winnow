Why Winnow

Retrieval is cheap. Sifting it honestly is not.

Search tools return lists. Deep-research tools write fluently from whatever they found, and sometimes from what they remember. Winnow is built for the part in between: identity, evidence, and the case against your own thesis.

01 — VERIFY

Verified, never generated

Five orthogonal axes: identity, match category, integrity notices, link status and check completeness. A DOI is resolved, not guessed. No model participates in deciding whether a paper exists.

02 — GROUND

Provenance, not vibes

Every evidence sentence carries a source and a quoted span. Synthesis needs two or more claims, gap claims come from corpus queries, and framing prose carries no facts. Weak support is flagged, not hidden.

03 — WEIGH

Ranked, not worshipped

Reciprocal rank fusion across providers, deterministic selection, and every candidate recorded with its provider ranks. Citation counts are shown, not treated as a quality score.

04 — ARGUE

Counter-evidence, with quotes

Inverted queries, citation chasing and stance labels (supports, opposes, mixed, unclear) with a quote behind each. A null result is a valid answer, not a failure.

What works now

A real CLI, verified against real indexes.

The v0.2 work retrieves, deduplicates, verifies and ranks. Briefs add a question, thesis, machine filters and exclusion flags. Screening is a human decision: the tool suggests, stores its suggestion separately, and never overwrites your call. Extraction starts only from human-confirmed includes, with every value tied to a quote. Stance labels are human-confirmed, and the argument map separates supporting, opposing, mixed and unclear evidence. A counter-evidence pass runs separately with critical terms. Drafting keeps only sentences that pass deterministic provenance and number checks; dropped sentences stay visible with their reasons. The writer can be a deterministic template or a local OpenAI-compatible model that sees only the evidence bundle; malformed output is rejected and every sentence still runs through the same checks. A separate support pass can mark partial statements and hold unsupported ones for review. Citations and references render through citeproc in APA, Vancouver or Harvard. Everything lives in one SQLite database, with raw provider payloads kept for replay.

Search saves to the nearest project by default. Use --no-save for an ephemeral run, or --format json|csv|bibtex|csl for exports. 

# install and link the CLI
npm install && npm run build
npm link ./packages/cli

# create a project and search
winnow init phd-review
cd phd-review
winnow search "retrieval augmented generation" --limit 20

# or use a brief: question, thesis, filters and exclusions
winnow brief briefs/question.md
winnow search --brief briefs/question.md --limit 20

# screen: tool suggests, human decides
winnow screen . --suggest
winnow screen . --interactive
winnow screen . --format csv --out exports/decisions.csv

# extract only from human-confirmed includes
winnow extract . --suggest
winnow extract . --format csv --out exports/evidence.csv

# draft from confirmed evidence; checks 1-5 run
winnow review . --out drafts/review.md
winnow review . --writer model --model qwen3:8b --out drafts/review.md
winnow review . --writer model --model qwen3:8b --support --out drafts/review.md
winnow review . --style vancouver --out drafts/review.md

# stance, argument map, counter-evidence pass
winnow stance . --thesis "Retrieval improves accuracy." --suggest
winnow argue . --thesis "Retrieval improves accuracy." --out drafts/argument.md
winnow counter . --topic "retrieval augmented generation" --thesis "Retrieval improves accuracy."

# verify one DOI, or every DOI in a file
winnow verify 10.1038/s41586-020-2649-2

# replay a run from its stored payloads
winnow replay <run-id>

Scope, stated plainly

Narrative and scoping reviews. Not a systematic-review engine.

v1 is honest about what a bounded search can support. A relevance-ranked top-N is not an exhaustive search. Winnow reports PRISMA-inspired flow counts, and says so. Exhaustive retrieval, per-database search strings, full-text eligibility and dual independent screening are deliberately deferred.

The design decisions are recorded in ADR 0001–0011, including the 2026-11-11 specification audit and its disposition.
